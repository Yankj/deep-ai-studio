## 这一期在讲什么

AI 把写代码提速之后，研发流水线最慢的一环挪到了测试，尤其是前端功能层面的端到端测试。文章按落地顺序拆了五个卡点：

1. 概念先对齐：单元、集成、功能、自动化描述的是不同维度，混着用会让每次讨论各说各话。
2. 运行时借现成的：不自建 Agent 循环，把测试能力做成插件挂在已有的编码 Agent 上。
3. 业务知识是半自动的根源：AI 能写用例，写不出业务跑在哪些端、哪条路径流量大；知识要用 Ontology 建成实体和关系，并跟着每个需求回写。
4. 执行难在稳定、进场和数据：真机、模拟器、网页分档，结论只算实际跑到的那一档。
5. 报告长在对话里：失败归因、重跑、回写知识库都在同一个界面里完成。

文中的状态写的是「在一部分需求上能从用例跑到执行，开头和过程中仍要人补业务、盯关键步骤」。这套方案没有全自动，正式端到端验收也还没有通过，归档时保持这个口径。
