# 写作与打磨规范

本规范沉淀自第 001 期创作过程，并在后续手记里修正了一处关键偏差：好用的分析框架，不能被写成每篇都一样的作文模板。目标不是把文章写得「像分析」，而是让读者先看见自己已经感知到的现象或体感，再被带进一层层更硬的判断。

相关文档：[人格档案](../persona/identity.md)、[内容创作 Skill](../skills/ai-content-craft/SKILL.md)。

## 1. 核心分析框架：道 / 法 / 术

讨论与构思按三层推进，不要停留在信息搬运。这是想清楚问题的方法，**不是成稿必须露出的章节名，也不是每篇文章都要走一遍的固定节奏**。

| 层级 | 要回答的问题 | 写法要求 |
| :--- | :--- | :--- |
| **术** | 最近到底发生了什么？一手信号或一线体感是什么？ | 先对齐关键事实、时间线、价格、使用感受和信源边界。把「已确认 / 仍存疑 / 只是叙事」分开写，不把传闻写成定论。 |
| **法** | 各方为什么这么做？压力如何传导？ | 拆清相关方各自的目标函数，以及事件或产品机制在时间线上的功能分工。 |
| **道** | 这件事揭示了什么不变的结构？ | 落到第一性原理：治理极限、供给确定性、协作机制、商业模式里真正被改写的那一层。 |

可以先把时间线或体感讲清楚，再把法和道嵌进判断里。不要在正文里写出「术 / 法 / 道」标签，也不要为了框架完整，再补一段和主题无关的升华。

## 2. 开头破局：从现象切入，不要虚空开场

禁止用「在现代商业史上……」「很少有一位……」「随着 AI 的快速发展……」这类宏大但含糊的句子开场。读者看了不知道你在说哪一件事，距离立刻被拉开。

正确做法：

1. **先抛读者已经看到的具体现象，或作者自己的具体体感**：明确时间点、价格、人事变动、刷屏事实、掏钱后的落差、前后反差。
2. **再用一两句点出反差或别扭之处**：例如「业绩仍在高位、没有公开接班布局，却在极短时间内完成交接」；或「两边都是 200 美元档，耐用程度却完全不是一回事」。
3. **自然引出要算的账**：为什么偏偏在这个点上值得写？背后在比什么？会带来哪些变化、机会和挑战？
4. **如果需要，再轻轻告诉读者接下来怎么拆**；不需要时，直接进入叙述，不必先宣布文章结构。

开场要像跟读者并排看同一件事，而不是从山顶宣布一个时代。

## 3. 结构组织：判断要有抓手，结构跟内容走

产业事件深稿可以参考下面的骨架，但**不是唯一合法结构**。使用手记、人物报道、视频脚本应按材料自身的节奏来，不要为了「像一篇规范的深度」去凑模块。

可选骨架（仅供产业事件深稿参考）：

1. 现象引子（发生了什么，反差在哪）
2. 分析任务（今天算哪几笔账）
3. 时间线（按阶段拆，并写清各阶段的功能）
4. 几个真正站得住的核心判断
5. 自然收束（见第 4 节，不设固定句式）

### 时间线怎么写

不要只罗列日期。每一段都要同时回答两件事：**发生了什么**，以及**这一波在整场事件里承担什么功能**。例如：先引爆外部争议、再给出治理上可执行的切割依据、离职后则转向叙事定调。读者看完节奏，很多因果不用猜就通了。使用手记则用体验顺序代替事件时间线，同样要写出每段体感在说明什么。

### 小标题怎么用

需要小标题时，每个判断配一个**简练、犀利、有抓手**的句子，让人能记住观点，而不是看到「浅析 / 简评 / 几点思考」。

标杆示例：

- 需求未崩塌，供应侧 AMD 与定制芯片或成最大受益者
- 私人风波只是触发器，本质是不确定性风险无法被接受
- 资本市场看「稳」，创业生态怕「收」

好标题的标准：有对象、有判断、有方向；尽量一句说完，不堆从句。

同时明确一条反例：**不要为了对仗，把全文切成字数接近、结构对称的 PPT 式小标题。** 标题是为了把判断钉住，不是为了让版面看起来很工整。一段话能走完的部分，不必硬加标题。

### 片段之间的概括性子标题

为可读性，可在文章片段之间加一句概括性子标题，把读者从一段体感带到下一层判断。

硬约束：

- 标题必须是该段的**根因或判断**，例如「高档位一拧，200 刀说没就没」「协作的问题不是人多，是先广播再静音」。
- 不要写成「背景 / 分析 / 总结 / 几点思考」这类分类标签。
- 仍然禁止 PPT 式对称小标题：不追求字数对齐、逻辑对仗、段落均分。不需要就不要加。

说明：上述「受益者」一类表述适合深度专栏的观点力度；若同步发放到短视频平台，需按发布规范把金融导向措辞再收一档，见 [抖音发布规范](./douyin-publishing-guide.md)。

## 4. 语言与收尾

- **先砍水分再谈文采。** 能用一句说清的不用三段铺垫；时间、职务、价格、因果尽量写实，少用「可谓」「不得不说」「值得注意的是」。
- **禁止说教和 AI 腔。** 不要空喊「我们应从中吸取教训」，不要用排比堆砌假装深刻。语气像在对一个聪明的同行讲话：有锋芒，但不轻浮。
- **把边界写清楚。** 调查结论、未证实事项、市场波动、个人体感和产业趋势，不要混成同一等级的事实。
- **不要写「结语」，也不要使用固定收尾句。** 旧规范曾要求统一落到「最后，下一个关键观察点在哪？」。这条已经明确作废。那种收法用在产业观察里偶尔合适，一旦变成每篇标配，读起来就像同一台机器在收工。收尾必须贴合本文自然落笔：可以停在一个可验证的观察点，也可以是具体用法、余韵、判断或留白。检查方法很简单——如果把这篇结尾和上一篇对调仍然通顺，就重写。

## 5. 去 AI 味与反套路准则

这是对本规范前几节的硬约束，写作和改稿时优先执行。

1. **禁止固定结尾模板。** 不再使用「最后，下一个关键观察点在哪？」以及「结语 / 总而言之 / 综上所述」。每篇收尾只对这一篇负责。
2. **禁止工整对称的 PPT 式小标题。** 不追求字数对齐、逻辑对仗、段落均分。标题要有刺，或者干脆不要标题。
3. **禁止空洞端水排比。** 「不是 A，而是 B」「既是 A，也是 B」「各有千秋」「谁也还没完全交卷」这类句子能不用就不用。判断清楚就直接说。
4. **保留真实一线体感与节奏变化。** 允许写花钱速度、工具别扭、协作翻车、克制的脾气。段落长短、语气松紧应随内容变化，不要写成每段都一样稳的标准深度文。
5. **开场和结构都不能套路化。** 具体现象或体感切入仍然有效；但不要每篇都「现象 — 任务 — 三点判断 — 下一个观察点」。材料不支持时间线，就不要硬造时间线。

## 6. 发布前自检清单

成稿后先自己过一遍，再考虑发出或归档。

### 主题与结构

- [ ] 标题是否准确提取主题，而不是空泛抒情？
- [ ] 开头是否从具体现象、体感、强反差或明确时间点切入？
- [ ] 结构是否跟内容走，而不是在套同一副骨架？
- [ ] 判断是否站得住？若使用小标题，是否有抓手，且没有沦为 PPT 式对仗？
- [ ] 片段之间若有子标题，是否是该段的根因或判断，而不是「背景 / 分析 / 总结」这类分类标签？
- [ ] 收尾是否只属于这一篇，而不是固定模板或空洞升华？
- [ ] 是否已同轮交付 60 字以内描述，以及带主题文字的 3:4 海报封面？中文字形是否正确？

### 论证与事实

- [ ] 一手信号或一线体感是否对齐？关键数字、日期、职务、价格是否核对过？
- [ ] 「已确认事实」和「推演判断」是否分开表述？
- [ ] 观点是否足够锋利，还是停在信息复述？
- [ ] 产业影响是否写到了需求、供给、客户行为或真实用法，而不只是情绪和排比？

### 表达

- [ ] 是否还有套话、重复论证或可删除的过渡段？
- [ ] 是否出现了端水排比、对称小标题或和上一篇同构的结尾？
- [ ] 读起来是否像在交流，而不是在宣读？
- [ ] 若需公开发布，是否已按平台规范做过高风险措辞检查？

## 7. 一期满档最低标准

产业事件深稿每期至少包含：

| 文件 | 作用 |
| :--- | :--- |
| `issues/.../README.md` | 总览卡片：标题备选、短描述、封面说明、配乐建议、核心信源 |
| `issues/.../article-final.md` | 可发布的合规终稿 |
| `issues/.../retrospective.md` | 过程复盘：改了什么、为什么改、下次默认怎么做 |
| `issues/.../cover-3x4.jpg` | 主题海报式封面：3:4 竖版，图上有主题文字，不是纯氛围图 |

使用手记、工具对照、随笔类期数可以不硬凑时间线和全过程复盘，但正文、60 字以内描述与主题海报封面须在成稿同轮交付。无论哪一类，仓库为公开仓库：只归档脱敏后的方法论、替换原则和可公开正文，不保存未脱敏的高风险原文或密钥。

## 8. 成稿同轮交付：主题海报封面与 60 字描述

正文定稿的同一轮，必须同时交出两样东西，不要先发文、后再补封面或描述。

1. **60 字以内描述。** 把这篇最硬的判断压进 60 字，供平台简介和期数索引使用。不写空泛抒情；话题标签如需另附，不要拿来充这 60 字。
2. **主题海报式封面，不是纯氛围图。** 封面根据主题设计，图上要有几个主题文字，必要时可用艺术字。短视频 / 竖版默认 3:4。

设计顺序：

- 先定读者 1 秒内要读出的判断，而不是先找一张好看的底图再硬贴字。
- 再用构图、隐喻和文字层级去支撑这个判断：主标题 + 1–2 条副信息。
- 文字可以做艺术处理，但不要堆砌；层级要一眼分得清。
- 中文必须字形正确。优先先出无字底图，再后期排版叠字；不要把大段中文直接交给生图模型「写」在图上。

归档为 `issues/.../cover-3x4.jpg`，并在期数 `README.md` 写入 60 字描述、正文和封面链接。
