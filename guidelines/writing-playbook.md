# 写作与打磨规范

本规范沉淀自第 001 期创作过程，作为后续深度 AI 博文的默认工作流。目标不是把文章写得「像分析」，而是让读者先看见自己已经感知到的现象，再被带进一层层更硬的判断。

## 1. 核心分析框架：道 / 法 / 术

讨论与成稿都按三层推进，不要停留在信息搬运：

| 层级 | 要回答的问题 | 写法要求 |
| :--- | :--- | :--- |
| **术** | 最近到底发生了什么？一手信号是什么？ | 先对齐关键事实、时间线和信源边界。把「已确认 / 仍存疑 / 只是叙事」分开写，不把传闻写成定论。 |
| **法** | 各方为什么这么做？压力如何传导？ | 拆清董事会、资本市场、产业客户、规则制定者各自的目标函数，以及事件在时间线上的功能分工。 |
| **道** | 这件事揭示了什么不变的结构？ | 落到第一性原理：枢纽型企业的治理极限、供应链确定性、生态托底能否制度化。 |

推荐节奏：**先用术把时间线讲清楚，再用 3–5 个核心判断把法和道展开，最后落到下一个可验证的观察点。**

## 2. 开头破局：从现象切入，不要虚空开场

禁止用「在现代商业史上……」「很少有一位……」这类宏大但含糊的句子开场。读者看了不知道你在说哪一件事，距离立刻被拉开。

正确做法：

1. **先抛读者已经看到的具体现象**：明确时间点、关键人事变动、市场或舆论已经刷屏的事实、前后反差。
2. **再用一两句点出反差或荒诞感**：例如「业绩仍在高位、没有公开接班布局，却在极短时间内完成交接」。
3. **自然引出要算的账**：为什么偏偏在这个时间点发酵？背后各方在追求什么？会带来哪些变化、机会和挑战？
4. **告诉读者接下来怎么拆**：先理时间线，再给核心判断。

开场要像跟读者并排看同一则新闻，而不是从山顶宣布一个时代。

## 3. 结构组织：总分结构，判断要有抓手

推荐骨架：

1. 现象引子（发生了什么，反差在哪）
2. 分析任务（今天算哪几笔账）
3. 时间线（按阶段拆，并写清各阶段的功能）
4. 3–5 个核心判断（每个判断一个小标题）
5. 「最后，下一个关键观察点在哪？」

### 时间线怎么写

不要只罗列日期。每一段都要同时回答两件事：**发生了什么**，以及**这一波在整场事件里承担什么功能**。例如：先引爆外部争议、再给出治理上可执行的切割依据、离职后则转向叙事定调。读者看完节奏，很多因果不用猜就通了。

### 核心判断的小标题

每个判断必须配一个**简练、犀利、有抓手**的小标题，让人在目录里就能记住观点，而不是看到「浅析 / 简评 / 几点思考」。

标杆示例：

- 需求未崩塌，供应侧 AMD 与定制芯片或成最大受益者
- 私人风波只是触发器，本质是不确定性风险无法被接受
- 资本市场看「稳」，创业生态怕「收」

好标题的标准：有对象、有判断、有方向；尽量一句说完，不堆从句。

说明：上述「受益者」一类表述适合深度专栏的观点力度；若同步发放到短视频平台，需按发布规范把金融导向措辞再收一档，见 [抖音发布规范](./douyin-publishing-guide.md)。

## 4. 语言与收尾

- **先砍水分再谈文采。** 能用一句说清的不用三段铺垫；时间、职务、因果尽量写实，少用「可谓」「不得不说」「值得注意的是」。
- **禁止说教和 AI 腔。** 不要空喊「我们应从中吸取教训」，不要用排比堆砌假装深刻。语气像在对一个聪明的同行讲话：有锋芒，但不轻浮。
- **把边界写清楚。** 调查结论、未证实事项、市场波动和产业趋势，不要混成同一等级的事实。
- **不要写「结语」。** 收尾统一落到：**「最后，下一个关键观察点在哪？」** 把情绪收回可验证的时间点、数据和口径上。

## 5. 发布前自检清单

成稿后先自己过一遍，再考虑发出或归档。

### 主题与结构

- [ ] 标题是否准确提取主题，而不是空泛抒情？
- [ ] 开头是否从具体现象、强反差和明确时间点切入？
- [ ] 是否先理清时间线，再给出核心判断？
- [ ] 核心判断是否不超过 5 个，且每个都有犀利子标题？
- [ ] 收尾是否落到下一个关键观察点，而不是空洞升华？

### 论证与事实

- [ ] 一手信号是否对齐？关键数字、日期、职务是否核对过？
- [ ] 「已确认事实」和「推演判断」是否分开表述？
- [ ] 观点是否足够锋利，还是停在信息复述？
- [ ] 产业影响是否写到了需求、供给、客户行为和生态，而不只是股价情绪？

### 表达

- [ ] 是否还有套话、重复论证或可删除的过渡段？
- [ ] 读起来是否像在交流，而不是在宣读？
- [ ] 若需公开发布，是否已按平台规范做过高风险措辞检查？

## 6. 一期满档最低标准

每期至少包含：

| 文件 | 作用 |
| :--- | :--- |
| `issues/.../README.md` | 总览卡片：标题备选、短描述、封面说明、配乐建议、核心信源 |
| `issues/.../article-final.md` | 可发布的合规终稿 |
| `issues/.../retrospective.md` | 过程复盘：改了什么、为什么改、下次默认怎么做 |
| `issues/.../cover-3x4.jpg` | 如有封面，使用 3:4 竖版；优先无字版，便于叠加标题 |

仓库为公开仓库：只归档脱敏后的方法论、替换原则和合规终稿，不保存未脱敏的高风险原文或密钥。
