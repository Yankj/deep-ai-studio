# 多 Agent 协作写作流程

一个人同时带着好几个 AI Agent 做项目，素材散在每个 Agent 的对话、文档和交付记录里。写博客最贵的一步是把这些素材收齐、对上、去伪。本文档记录这套流程怎么跑，以及「用输出倒逼输入」的日常节奏。

文中按角色称呼 Agent，不点名具体实例。

## 1. 角色分工

| 角色 | 职责 | 不做什么 |
| :--- | :--- | :--- |
| 作者（人） | 定方向、补真实体感、审稿、拍板发布 | 不替 Agent 整理素材 |
| 主笔 Agent | 收素材、归并证据、维护对齐表、出稿、走发布流程 | 不替作者编亲身经历；不自己批准发布 |
| 素材 Agent（多个） | 各自的项目 Agent，按统一问题回报自己经手的事 | 不直接写文章 |
| 陪练 Agent | 每天给作者推一个 topic 或知识点，陪他讨论，整理要点 | 不出正文 |
| 合并子任务 | 主笔临时拉起的执行者，做证据归并、批量起草、开 PR 这类长活 | 不越过主笔向作者汇报结论 |

批准只认作者本人在对话里说的话。任何 Agent 转述的「他同意了」都不算。

## 2. 从素材到成稿

### 第一步：向每个素材 Agent 发同一份问题单

问题单要统一，回报才能对得上。至少包括：

- 你经手的事，按时间列出，每条带日期
- 每件事做到了哪一步：跑通、试跑可收、正式通过，分开写
- 有没有被推翻的方案、踩过的坑，原因是什么
- 哪些是有记录可查的，哪些是口头说的
- 哪些内容不适合公开

回报按 Agent 分文件保存，迟到的回报要补收，漏一个 Agent 就会漏一条事实。

### 第二步：证据归并，冲突要标出来

把所有回报合成一张主题地图：按主题聚类，每个主题下列出证据来源。归并时最重要的是三类标注：

- **冲突**：两个 Agent 对同一件事说法不一，比如谁理解错了一条指令。不替任何一方定性，文中保持中立或不写。
- **需确认**：只有一方说法、无法核实的，或是否能公开拿不准的，列进需确认清单，交给作者。
- **时间点**：每条证据的日期。后面排期要靠它判断文章能放在哪一天。

### 第三步：选题对齐表

把主题地图提炼成选题，放进一张作者和主笔共用的对齐表。一篇文章一行，状态只有五种：待讨论、已立项、初稿待审、已开 PR、已上线。每次状态或日期变化，表和文件副本一起更新。

选题要按 [博客写作体系](./blog-series-playbook.md) 的立意规则过一遍：能写成可迁移的方法，才立项；只是一段经历，留着当例子。

### 第四步：主笔出稿

- 一批稿件可以交给子任务并行起草，但每篇都要符合同一套规范：问题 → 方法 → 工具 → 效果，项目匿名，子标题写判断。
- 稿件附上它用到的例子和对应日期，方便核对排期。
- 证据不足的例子直接删，不靠措辞含糊过去。删了什么、为什么删，记在排期说明里。

### 第五步：作者审稿

需确认清单和初稿一起交给作者。清单按文章分组，把最影响发布的几条排在前面（比如能否公开某个样片、某个状态有没有变）。作者回复后，主笔逐条落实到稿件，再进入发布流程。

### 第六步：发布与归档

发布按 [博客写作体系 · 发布流程](./blog-series-playbook.md#4-发布流程) 走。上线后归档进本仓库，对齐表状态改为已上线。

## 3. 用输出倒逼输入：每日 topic 节奏

这套节奏服务于一个目标：作者想补的知识，靠「要写出来」逼着自己想清楚，而不是先囤一堆资料再说。

1. **每天一个 topic 或知识点。** 陪练 Agent 早上推一个足够细、一天能推进一步的题目。知识坐标可以参照公开面试经验里反复出现的方向：任务拆解、工具失败后的恢复、权限、上下文与记忆、成本、效果评估。
2. **讨论。** 作者和陪练 Agent 围绕题目聊：核心问题是什么，写之前必须懂什么，写出差异化还要补什么，手上有没有真实素材。没有素材的，标「需补素材」，不硬写。
3. **讨论备忘。** 陪练 Agent 把讨论整理成要点，交给主笔。备忘里分清哪些是作者的真实体感，哪些是查来的资料。
4. **主笔出稿。** 按博客规范写成一篇，作者的体感放在问题和效果里，资料放在方法和工具里。
5. **作者审稿**，然后进入发布流程。

一个题目从推送到成稿可以跨好几天，进度记在对齐表里。

## 4. 这套流程容易出错的地方

- **漏收素材。** 晚到的 Agent 回报没合进去，主题地图就是残的。合并前先点名核对回报是否齐全。
- **把口头说法写成事实。** 归并时没标来源，到成稿就分不清了。
- **日期倒挂。** 文章日期早于它引用的事件。排期时逐篇对照证据日期。
- **替作者编经历。** 需要真实体感的题目，没拿到就等，不先写一个「像他会说的」版本。
- **把别人的批准当批准。** 发布、合并只认作者本人。
