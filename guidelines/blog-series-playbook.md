# 博客写作体系：立意、板块、排期与发布

本文档管的是「博客上写什么、按什么顺序写、怎么发」。怎么把一篇写好，见 [写作规范](./writing-playbook.md)；去 AI 味和人格底线，见 [内容创作 Skill](../skills/ai-content-craft/SKILL.md)。

## 1. 立意：写可迁移的领域思考，项目只当例子

一篇博客要回答的问题是「别人在自己的场景里能拿走什么」。所以每篇都写成一条完整的链：

| 环节 | 要写清楚的东西 |
| :--- | :--- |
| 问题 | 一个具体现象：哪一步卡住了，代价是什么，为什么现有做法不够 |
| 方法 | 解决它的判断和做法，能脱离原项目被别人复用 |
| 工具 | 用了什么协议、框架、Agent 能力或流程，为什么选它，没选什么 |
| 效果 | 做到了哪一步、还差哪一步。没做到的写没做到，没验收的写没验收 |

几条硬规矩：

- **不写日记和项目流水账。** 「今天做了 A，明天做了 B」不进博客。时间顺序只在它能说明因果时才用。
- **具体项目一律匿名，只当例子。** 写成「一个亲子类 App」「一个儿童科普账号」「一个超级 App 的测试小队」，不写项目名、仓库、账号和内部代号。例子服务于方法，不反过来。
- **效果口径保守。** 跑通、试跑可收、正式通过是三回事，分开写；正式验收没过就写没过，不写「已闭环」「已全自动」。
- **数字只用核实过的。** 平台后台数据、未公开的内部指标不进正文；引用公开资料要写明出处和局限（比如数据主要来自单一仓库、是公司自述）。
- **子标题写根因判断**，开头从具体现象切入，标题一眼能懂。

## 2. 五大板块

板块按「这类文章能证明什么能力」来划，不按项目划。一个项目可以给多个板块供例子。

| 板块 | 写什么 | 典型题目方向 |
| :--- | :--- | :--- |
| 一、多 Agent 协作 | 一支 AI 小队怎么搭、怎么分权、怎么验收交付 | 先切权力再切活；「继续」不等于「合」；交付只认路径和校验值 |
| 二、AI 测试与自动化 | AI 测试在业务知识、真机执行、结果判定上的工程问题 | 业务知识以代码和真实数据为准；真机操作先定停止点；测试的「绿」要分级 |
| 三、AI 内容生产工作流 | 从选题、编剧到制作、质检、分发的 Agent 化流水线 | 自媒体 Agent 组的角色分工；几种视频风格各要一条工作流；机器门禁全绿之后人还要看什么 |
| 四、AI 原生产品开发 | AI 产品的交互、评测和多端验收 | 别让用户填表；先建评测集再换模型；把「体验不降级」写成能判 FAIL 的验收单 |
| 五、个人 AI 工作方法 | 个人用 AI 处理工具接入、事务、创作的取舍 | 接海外工具卡在哪几道门；哪些该自动化、哪些提醒就够 |

另有两类文章不进五大板块，单列：

- **Agent 技术基础**：运行时、Skill 与 Tool、RAG、上下文工程、评测、MCP 边界等通用概念和方法，可以只依赖公开资料来写。
- **行业观察**：产业事件和格局判断，按 [写作规范](./writing-playbook.md) 的产业深稿要求写。

## 3. 排期：文章日期不早于文中事件

博客按日期排文，排期要同时满足两件事：把空档填起来，并且每篇都站得住。

1. **日期不早于文中引用的任何事件或资料。** 一篇写 10 月中旬项目经历的文章，日期就不能落在 9 月。硬往前放，等于编造时间。
2. **素材到不了的空档，用方法论和公开资料补。** 比如 Agent 技术基础类文章，只引用发布时间早于文章日期的公开文章、论文和报道，不编亲身经历。
3. **同一天最多放两篇**，同一板块尽量不连发，避免读者看到一串同构的标题。
4. **撞题提前让路。** 已立项、等作者补真实体感的题目，其他稿件主动绕开这个角度。
5. **排期改动和选题状态放在同一张对齐表里维护**，状态分为：待讨论 → 已立项 → 初稿待审 → 已开 PR → 已上线。每次状态或日期变化都同步更新。

## 4. 发布流程

博客站点用 Quartz 构建，内容源头在一个私有知识库里，其中只有一个公开目录会被同步到博客。发布只走这条链路：

1. **触发**：作者明确说「定稿」才进入发布；封面和配图是否获批同时确认清楚，没批的图不进 PR。
2. **写入公开目录**：文章只写进私有知识库的公开目录，不直接改博客仓库。分类用已有的英文目录（concept / method / tool / insight），思考、复盘、行业判断默认放 insight。
3. **文件规范**：文件名 `YYYY-MM-DD_中间词_标题.md`，中间词跟分类走（思考、方法、工具、概念）；frontmatter 只用标准字段，H1 与标题一致，下面紧跟封面和 60 字以内导语；配图放分类的 assets 目录，小写连字符命名，单张不超过 3MB，所有链接都能解析。
4. **内容自检**：不放测试、样例和占位内容；脱敏账号、验证码、端口、设备 ID、内网主机名、公司名；涉及真实人物的负面事实先请作者确认。
5. **本地校验**：在本地跑知识库的笔记校验和公开内容导出，把导出结果放进博客本地副本，再跑内容校验和 Quartz 构建，本地预览确认。测试只在本地做，线上站不当试验场。
6. **开 PR，等「合」**：新开分支、普通提交、开 PR，附清单和预览截图。作者明确回「合」或「合并」才合；其他 Agent 转述的批准不算数。
7. **首页目录手动补**：博客首页目录是手工维护的，同步不会更新它。每次新增文章，在对应分类下补链接（同一个 PR 或紧跟一个 PR）。
8. **上线核对**：同步和部署都成功后，逐篇确认文章和封面返回正常、标题在页内、首页目录出现新文章，再把线上链接发给作者。Quartz 会把 slug 里的英文字母转成小写，链接以实际地址为准。

## 5. 每次创作后的两件事

每完成一次新创作，主笔主动做两件事，不等提醒：

1. **更新博客**：定稿的文章按第 4 节发布；未定稿的在对齐表里更新状态。
2. **沉淀本仓库**：已上线的文章归档为一期（正文、60 字描述、已获批封面、需要时附复盘）；写作中学到的新规矩写回 [写作规范](./writing-playbook.md)、[内容创作 Skill](../skills/ai-content-craft/SKILL.md) 或本文档，并在 [CHANGELOG](../CHANGELOG.md) 记一笔。

未发布的初稿只在 README 里登记系列和篇数，不放全文；定稿上线后再归档。
